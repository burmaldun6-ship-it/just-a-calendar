# Безопасность

## Что делает приложение

Календарь работает офлайн. В манифесте нет разрешения `INTERNET` и опасных
разрешений Android. Приложение не содержит рекламы и аналитики.
Локально сохраняются только тема, переключатель обновления даты и его интервал.

AndroidX добавляет внутреннее permission с уровнем `signature`:
`local.minicalendar.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`.
Это защита внутренних broadcast receiver, а не доступ к данным телефона.
В объединённый манифест также входят стандартные компоненты AndroidX Startup
и ProfileInstaller. Receiver ProfileInstaller защищён системным `android.permission.DUMP`.

`allowBackup=false` дополнен правилами исключения cloud-backup, full-backup
и device-transfer. Поведение переноса на всех OEM-устройствах не проверялось.

## Сборка и подпись

- Дистрибутив Gradle и Wrapper JAR проверяются по SHA-256.
- Зависимости проверяются в strict-режиме по `gradle/verification-metadata.xml`.
- Версии зависимостей приложения закреплены в `app/gradle.lockfile`.
- GitHub Actions закреплены по commit SHA; права workflow — только чтение.
- CI не получает ключей подписи и не публикует релизы автоматически.

Первичная генерация checksums выполнена по артефактам из настроенных
репозиториев. Это обнаруживает последующие изменения, но не заменяет аудит
зависимостей и независимую проверку издательских подписей.

R8 и короткие имена уменьшают код; они не шифруют данные и не защищают секреты.

**Никогда не публикуйте** keystore, `.p12`, пароль, `local.properties`,
приватный архив резервного ключа или логи, содержащие секреты.
`.gitignore` и `scripts/check_repo.py` дают дополнительную проверку,
но не являются полноценным сканером секретов и не очищают историю Git.
Если секрет уже попал в Git, простого удаления файла недостаточно.

## Сообщить о проблеме

Не прикладывайте секреты и ключи к публичным Issues. Если в репозитории
доступен раздел **Security → Report a vulnerability**, используйте его.
Иначе сначала создайте Issue с просьбой предоставить приватный способ связи,
без чувствительных подробностей. Выделенной службы поддержки и обещанного
срока реакции у личного проекта нет.
